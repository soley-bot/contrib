# Cache & Cold-Start Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Contrib feel fast by eliminating client-side fetch waterfalls, dead dependencies, and static imports of heavy libraries that do not need to be on the initial render path.

**Architecture:** Three kinds of wins, in ROI order. (1) Delete dead `ai` + `@ai-sdk/react` dependencies that ship zero functionality. (2) Lazy-load `jspdf` (heavy, rarely used) via `await import('jspdf')` inside `lib/pdf.ts` so it is not in the initial bundle of four pages. (3) Adopt SWR for read hooks so navigation becomes instant (cache + dedup + stale-while-revalidate) instead of every page remount triggering full refetches. Fluid Compute (Vercel default on Next 16) already handles server cold starts — we only need to verify it is enabled, not change code.

**Tech Stack:** Next.js 16.1.6 Pages Router, React 19, TypeScript strict, Supabase client, `swr` (new), `jspdf` (existing, moving to lazy load).

**Measurement evidence driving this plan:**
- `ai` (7.5 MB) + `@ai-sdk/react` (2.8 MB) in `package.json` — **zero imports anywhere in the codebase** (`grep "from 'ai'|from '@ai-sdk'"` returns nothing).
- `jspdf` (29 MB unpacked, ~300 KB minified) is **statically imported** in `lib/pdf.ts:1` and pulled into the initial bundle of 5 call sites: `pages/group/[id].tsx:29`, `pages/report/[token].tsx:4`, `pages/teacher/course/[id]/index.tsx:18`, `pages/teacher/course/[id]/group/[groupId].tsx:18`.
- `generateReport()` at `lib/pdf.ts:110` is **synchronous** today, and `jsPDF` is constructed at `lib/pdf.ts:124` (`new jsPDF({ unit: 'mm', format: 'a4' })`).
- 22 of 22 hooks in `contrib/hooks/` use the `useState + useEffect + supabase → setState` pattern. **Zero** use SWR, React Query, or any shared cache.
- `getServerSideProps` exists on 13 pages but **only guards auth and returns `{ props: {} }`** — it does not prefetch any data. Example: `pages/dashboard.tsx:398-402`.
- `group/[id].tsx` mounts **10 independent hooks simultaneously** (`useUser`, `useGroup`, `useTasks`, `useActivity`, `useGroupEvidence`, `useEvaluationSession`, `useEvaluation`, `useEvaluationSummaries`, `useShareLink`, plus child-tab hooks). No dedup of overlapping queries.
- **No `next/dynamic` anywhere** in the codebase. No code splitting of heavy components or libs.
- **TOCTOU hardening is explicitly out of scope** — documented as deferred work in `contrib/CLAUDE.md`.

```tsx
import { createContext, useContext, type ReactNode } from 'react';
import useSWR from 'swr';
import * as Sentry from '@sentry/nextjs';
import { supabase } from '@/lib/supabase';
import type { Profile } from '@/types';

interface ProfileContextValue {
  profile: Profile | null;
  loading: boolean;
  error: string | null;
  refresh: () => void;
}

const ProfileContext = createContext<ProfileContextValue | null>(null);

async function fetchProfile(userId: string): Promise<Profile | null> {
  const { data, error } = await supabase
    .from('profiles')
    .select('id, name, email, university, faculty, year_of_study, role, telegram_chat_id, notification_prefs, created_at')
    .eq('id', userId)
    .single();
  if (error) {
    Sentry.captureMessage(`profile-provider fetch failed: ${error.message}`, { level: 'error' });
    return null;
  }
  return data as Profile;
}

interface ProviderProps {
  userId: string | undefined;
  children: ReactNode;
}

export function ProfileProvider({ userId, children }: ProviderProps) {
  const { data, error, isLoading, mutate } = useSWR(
    userId ? ['profile', userId] : null,
    ([, id]) => fetchProfile(id),
  );

  const value: ProfileContextValue = {
    profile: data ?? null,
    loading: isLoading,
    error: error ? 'Failed to load profile.' : null,
    refresh: () => { void mutate(); },
  };

  return <ProfileContext.Provider value={value}>{children}</ProfileContext.Provider>;
}

export function useProfileContext(): ProfileContextValue {
  const ctx = useContext(ProfileContext);
  if (!ctx) throw new Error('useProfileContext must be used inside <ProfileProvider>');
  return ctx;
}
```

## Task 4: Migrate four highest-traffic read hooks to SWR

**Why only four:** The rest can follow mechanically once this task proves the pattern for hooks that also subscribe to Supabase realtime channels. These four cover the majority of page loads.

**Pattern for every realtime-aware hook:**
1. Replace `useState + useEffect + fetch` with `useSWR(key, fetcher)`.
2. Keep the realtime channel `useEffect`, but inside the channel callback call `mutate(key)` instead of re-running the fetcher manually.
3. Expose `refresh: () => mutate(key)` so existing callers of `refresh()` keep working.

- [ ] **Step 1: Migrate `use-groups.ts`**

Read the current file fully (it is ~57 lines). Then rewrite. The new version:

```ts
import { useEffect } from 'react';
import useSWR from 'swr';
import * as Sentry from '@sentry/nextjs';
import { supabase } from '@/lib/supabase';
import type { Group } from '@/types';

interface UseGroupsResult {
  groups: Group[];
  loading: boolean;
  error: string | null;
  refresh: () => void;
}

async function fetchGroups(userId: string): Promise<Group[]> {
  const { data, error } = await supabase
    .from('group_members')
    .select('group:groups(id, name, subject, due_date, lead_id, course_id, archived_at, created_at)')
    .eq('profile_id', userId);
  if (error) {
    Sentry.captureMessage(`Failed to load groups: ${error.message}`, { level: 'error' });
    throw new Error('Failed to load data.');
  }
  return ((data ?? []) as Array<{ group: unknown }>)
    .map((row) => row.group as Group)
    .filter(Boolean);
}

export function useGroups(userId: string | undefined): UseGroupsResult {
  const key = userId ? ['groups', userId] : null;
  const { data, error, isLoading, mutate } = useSWR(
    key,
    ([, id]) => fetchGroups(id),
  );

  useEffect(() => {
    if (!userId) return;
    const channel = supabase
      .channel(`user-groups:${userId}`)
      .on('postgres_changes', {
        event: '*',
        schema: 'public',
        table: 'group_members',
        filter: `profile_id=eq.${userId}`,
      }, () => {
        void mutate();
      })
      .subscribe();
    return () => { supabase.removeChannel(channel); };
  }, [userId, mutate]);

  return {
    groups: data ?? [],
    loading: isLoading,
    error: error ? error.message : null,
    refresh: () => { void mutate(); },
  };
}
```
